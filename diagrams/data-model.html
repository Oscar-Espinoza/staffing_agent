Staffing Risk Agent · Data Model

Three systems, no shared key

Kantata, Salesforce and ClickUp share nothing but an email address. Everything downstream of model-record.ts is one outer union on that address, a hand-maintained client map, and a short list of joins the code deliberately refuses to make.

JOIN 1 OF 3

Joined on email, because nothing else matches

  • No shared identifier exists across Kantata, Salesforce and ClickUp
  • Key is email.trim().toLowerCase(), zod-validated
  • Outer union: a person may exist in one system, two, or all three
  • A duplicate email within one provider throws rather than guessing
  • isExternal is derived: domain !== 'gonimbly.com'

JOIN 2 OF 3

The client map is hardcoded on purpose

  • Eight entries in src/clients.ts, one per known client
  • The systems disagree: Quillspace → Quillspace Software
  • And again: Ironvale → Ironvale Data Group
  • ClickUp list names diverge further: Halden → Halden Phase 2
  • A miss accumulates in unmappedClients — never fuzzy-matched, never guessed

WHAT'S LEFT OUT

Deliberately not joined

  • ClickUp assigneeIds to Person.clickupMemberId — activity context, never capacity
  • matchedDeals is an account-level join, so it cannot prove a deal funded a project
  • A dangling projectId still counts toward the person's total, but attaches to no project
  • That drop lands in notes[] as a data-quality note, never as a finding

Every join here was chosen to fail loudly rather than quietly. A duplicate email throws, an unmapped client accumulates, a dangling allocation is recorded — the one thing the code never does is invent a match.
