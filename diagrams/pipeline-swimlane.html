Staffing Risk Agent · Pipeline

One run, and the one thing the model decides

Ten collections fetched once, one deterministic join, five arithmetic detectors, a single bounded OpenAI call, seven ways to throw its answer out — then one Slack message, or none.

MODEL INPUT

What the model is allowed to see

  • Per opportunity: id, name, accountName, stage
  • Per project: id, title, clientName — Active only
  • Withheld: amounts, probabilities, hours, every date, all allocations, all leave, all capacity, all person names
  • The payload is hand-built field by field, never a spread — a field it never sees is a fact it cannot fabricate

GROUNDING

Seven ways a link gets thrown out

  • unknown_opportunity, missing_project, relation_mismatch
  • unknown_project, unresolved_record, cross_client, duplicate_opportunity
  • cross_client re-derives the client map in code rather than trusting the answer
  • A clean unrelated verdict is skipped and counted as neither a link nor a rejection, so the number stays honest

DEGRADED MODE

When the model is down

  • Any of not_configured, request_failed, invalid_response, no_candidates returns an empty Map
  • detectFollowOn then emits zero findings
  • All five deterministic detectors already ran and are untouched — no throw, no 500
  • clientMatchBaseline reports every run whether the model was needed at all: 1 candidate means arithmetic sufficed, 2+ means only free-text names could choose

The model sits in its own lane for one column and returns three fields. Everything it hands back crosses straight into deterministic code to be checked against the client map before any of it can become a finding — and if the call never happens, the run completes anyway.
